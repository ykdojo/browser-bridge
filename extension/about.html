Browser Bridge

Let an AI agent use the Chrome you are already logged into.

Browser automation usually starts a fresh, logged-out browser. Browser Bridge is a small extension plus a local MCP server that gives Claude Code, or any other MCP client, the tabs in your real Chrome instead.

What happens when the agent clicks a button

  1. The agent reads the page.read_page sends Accessibility.getFullAXTree across the bridge and turns the result into indented text. Every element gets a ref in brackets.
  2. The agent picks a ref.It calls computer with left_click and that ref. No pixel guessing needed, though clicking a point read off a screenshot works too.
  3. The server finds where the element is.DOM.scrollIntoViewIfNeeded, then DOM.getBoxModel to get the center point.
  4. Chrome performs a real click.Input.dispatchMouseEvent sends move, press and release. The page sees a trusted event, the same as a person clicking.

What the agent sees

This is real read_page output for example.com. It is the page's accessibility tree, the same structure a screen reader uses.

The twelve tools

Names and input shapes are kept consistent with Claude for Chrome's.

ToolWhat it does
tabs_contextTabs the agent can see, and whether each one can be controlled
tabs_createOpen a new tab, logged in as you
tabs_closeClose a tab
navigateGo to a URL, back or forward, and wait for the page to load
read_pageAccessibility tree as text, with a ref on every element
findLook elements up by description, get refs back
get_page_textThe page's readable text, for articles and long pages
computerMouse and keyboard by ref or by pixel: clicks, typing, keys, scrolling, hover, drag, screenshot, zoom
form_inputSet a field's value directly: text, checkboxes, radios, dropdowns
javascript_toolRun JavaScript in the page and get the result back
read_console_messagesConsole output and uncaught errors, filterable
read_network_requestsRequests the page made, with status

Which tabs the agent gets

Every open tab in the Chrome profile where the extension is loaded, and nothing from other profiles. Loading it in a separate profile is an easy way to keep an agent away from your main logins. Chrome's own pages, like chrome://extensions, show up in the list but cannot be read or controlled. Chrome does not allow it.

What keeps it safe, and what does not

  • The server listens on 127.0.0.1 only and accepts a WebSocket only from this extension's ID. Browsers always send a truthful Origin header, so web pages and other extensions are rejected.
  • A program already running on the machine could fake that header. This is not a defense against malware.
  • The agent can reach every logged-in tab, so any page it reads could try to steer it toward the others. There is no per-tab scoping and there are no confirmation prompts yet.
