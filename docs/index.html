Chrome Bridge

Let an AI agent use the Chrome you are already logged into.

Browser automation usually starts a fresh, logged-out browser. Chrome Bridge is a small extension plus a local MCP server that gives Claude Code, or any other MCP client, the tabs in your real Chrome instead.

What happens when the agent clicks a button

  1. The agent asks for a snapshot.The server sends Accessibility.getFullAXTree across the bridge and turns the result into indented text. Every element gets a number in brackets.
  2. The agent picks a number.It calls click with that ref. No screenshots or pixel guessing needed.
  3. The server finds where the element is.DOM.scrollIntoViewIfNeeded, then DOM.getBoxModel to get the center point.
  4. Chrome performs a real click.Input.dispatchMouseEvent sends move, press and release. The page sees a trusted event, the same as a person clicking.

The ten tools

ToolWhat it does
list_tabsTabs the agent can see, and whether each one can be controlled
new_tabOpen a URL in a new tab, logged in as you
close_tabClose a tab
navigateGo to a URL and wait for the page to load
snapshotAccessibility tree as text, with a ref on every element
clickClick a ref, or x and y coordinates
typeType into the focused element or a ref, optionally press Enter
press_keyEnter, Tab, Escape, arrows, single characters
screenshotJPEG of the visible page, for when layout matters
evaluateRun JavaScript in the page and get the result back

Which tabs the agent gets

All of them. Every open tab in the browser is available, with no per-tab setup. Chrome's own pages, like chrome://extensions, show up in the list but cannot be read or controlled. Chrome does not allow it.

Why it is built this way

chrome.debugger instead of content scripts
It gives trusted input events, the accessibility tree and screenshots, and it works on any site. The cost is a "started debugging this browser" bar while it is attached.
A WebSocket instead of native messaging
Installing it stays a two-step job: add the extension, run one command. Native messaging needs a manifest file installed per operating system.
A thin extension
The extension only relays commands. The logic is in the server, so most changes need no extension reload.
Several agent sessions at once
The first server to start owns the port and the extension connection. Later ones join it as peers and get relayed. If the first one exits, a peer takes over and the extension reconnects in about two seconds.

What keeps it safe, and what does not

  • The server listens on 127.0.0.1 only and accepts a WebSocket only from this extension's ID. Browsers always send a truthful Origin header, so web pages and other extensions are rejected.
  • A program already running on the machine could fake that header. This is not a defense against malware.
  • The agent can reach every logged-in tab, so any page it reads could try to steer it toward the others. There is no per-tab scoping and there are no confirmation prompts yet.

Setup

  1. Install the server's dependencies.cd server && npm install
  2. Load the extension.Open chrome://extensions, turn on Developer mode, choose "Load unpacked" and pick the extension folder.
  3. Register the server with the agent.claude mcp add -s user chrome-bridge -- node <repo>/server/index.js
